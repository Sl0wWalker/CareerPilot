# M14 — Platform APIs, SDKs, and Extensibility

## Outcome

CareerPilot now exposes a stable `/api/v1` platform surface for local integrations.
Developers can create revocable API keys, authenticate public API calls, subscribe to
live events over WebSockets, configure webhooks, and manage discovered plugins from
the Developer Portal.

## Architecture

- Existing OAuth2-style bearer authentication remains the user and administrator
  authentication mechanism.
- Integration clients use scoped API keys. Only the SHA-256 digest is stored; the
  secret is displayed once.
- Existing global request middleware provides configurable per-client rate limiting.
- OpenAPI remains the canonical REST contract at `/openapi.json` with interactive
  documentation at `/docs`.
- `EventBus` provides typed in-process publish/subscribe and powers the WebSocket
  event stream.
- Python entry points provide extension discovery without coupling the core to plugin
  implementations.

## Plugin extension points

Third-party Python packages register entry points in one of these groups:

```toml
[project.entry-points."careerpilot.ai_providers"]
my_provider = "my_package:provider"

[project.entry-points."careerpilot.job_sources"]
my_board = "my_package:source"

[project.entry-points."careerpilot.automation_adapters"]
my_ats = "my_package:adapter"
```

Discovered plugins are disabled by default and require explicit activation.
Interfaces are defined as Python protocols in
`careerpilot.services.platform`.

## SDKs and samples

- `sdk/python` contains the official Python client.
- `sdk/typescript` contains the official TypeScript client.
- `samples/` contains minimal authenticated examples for both SDKs.

## Security boundaries

- API keys are revocable and scoped.
- Plugin configuration is persisted locally.
- Plugins are never enabled automatically.
- WebSocket clients must authenticate with a valid API key.
- Webhook secrets are generated per subscription and are not returned by list APIs.

## Deferred work

Durable cross-process event brokers, asynchronous webhook delivery workers, an
OAuth authorization-code server, plugin signature verification, and SDK generation
from OpenAPI are production-scale extensions. The M14 contracts deliberately leave
room for those capabilities without requiring cloud infrastructure.
