# M15 — Enterprise, Scalability & AI Agent Ecosystem

## Outcome

CareerPilot now has an enterprise control-plane foundation while preserving its
local-first deployment model. The implementation adds tenant-aware
organizations and workspaces, RBAC memberships, SSO configuration foundations,
policy and quota enforcement, auditable agent orchestration, scoped memory,
licensing records, and an enterprise administration workspace.

## Architecture

The enterprise module extends the M14 platform API and event bus rather than
creating a second integration system:

```text
Organization
  ├─ Workspace
  ├─ Membership / RBAC
  ├─ OIDC or SAML configuration
  ├─ Policies and quotas
  ├─ Audit events
  ├─ Agent runs and scoped memory
  └─ License / billing metadata
```

Tenant-owned records carry an `organization_id`. Workspace-specific workflows
also carry a `workspace_id`. Enterprise routes require the existing owner/admin
security dependency, and mutations emit audit records.

## Agent ecosystem

Agent runs form a durable orchestration envelope with:

- agent type and objective;
- tenant and optional workspace scope;
- parent run for delegation trees;
- JSON input/output contracts;
- queued/running/terminal status;
- error capture;
- tenant-scoped memory;
- quota consumption; and
- M14 event-bus notifications.

The initial queue backend is database-local so personal deployments remain
free and simple. A production deployment can replace the execution layer with
Redis, RabbitMQ, SQS, or another broker without changing API contracts.

## Enterprise identity

OIDC and SAML settings are configuration foundations only. Secret exchange,
metadata validation, assertion verification, SCIM provisioning, and identity
provider certification must be completed and independently security-reviewed
before production SSO is enabled.

## Billing and licensing

Licenses and usage quotas are deliberately provider-neutral. No paid billing
service is required. A future billing plugin may map external customer and
subscription identifiers onto these records.

## Observability and compliance

Enterprise mutations create append-oriented audit events. The overview endpoint
reports tenant, membership, agent, quota, and queue health. Existing M9
operational middleware and M14 webhooks/event streaming remain the integration
points for metrics and SIEM export.

## API

The new `/api/v1/enterprise` API supports:

- organization and workspace creation;
- membership and role assignment;
- OIDC/SAML configuration;
- policy and quota upserts;
- agent queueing and listing;
- agent-memory upserts;
- audit-log reads; and
- enterprise health summaries.

## Deployment guidance

Single-node installations may continue using SQLite and the local queue.
Horizontally scaled deployments should use PostgreSQL, shared object storage,
a distributed broker, stateless API replicas, external secret management, and
an ingress that provides TLS and trusted identity headers. See
`docs/ENTERPRISE_DEPLOYMENT.md`.

## Intentional limits

- SSO is not a complete identity-provider implementation.
- Billing records do not charge users.
- The database-local queue does not execute agent work across nodes.
- Organization administration is restricted to existing owner/admin roles.
- Cross-tenant access is denied by tenant-scoped resource lookup patterns.
