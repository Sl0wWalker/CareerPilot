# M7 — Intelligent Application Automation

M7 adds a supervised, resumable application automation foundation. It detects
Greenhouse, Lever, Ashby, Workday, and generic forms; maps visible fields to the
verified Career Knowledge Base and approved screening answers; records run
checkpoints; and requires explicit human approval.

## Safety model

- Dry-run is the default.
- Draft resumes cannot be used.
- Sensitive, legal, demographic, compensation, authorization, and signature
  fields always require review.
- Missing required values block approval.
- The Playwright runner contains no final-submit action.
- CAPTCHA and authentication challenges are expected to pause for the user.
- Session state is referenced by a private local path and is never stored in Git.

## Architecture

`AutomationService` owns state transitions and validation.
`AutomationRepository` owns persistence. ATS adapters own page-specific
detection and selectors. `PlaywrightRunner` owns browser mechanics and stops at
final review. API routes remain thin.

Run lifecycle:

`queued → inspected → needs_review/ready → user_approved → dry_run_complete`

Each run stores its adapter, document choices, mapped-field snapshot, validation
errors, attempt count, and last safe checkpoint. Steps provide an immutable
history suitable for retry and diagnostics.

## Extension points

Adapters can replace generic selectors with ATS-specific inspection, upload, and
validation behavior. A later milestone may add browser-session capture,
screenshot artifact retention, interactive CAPTCHA pauses, and an explicit
second-factor submission endpoint. None should bypass the approval gate.
