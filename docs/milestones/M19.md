# M19 — CareerPilot 2.0 Innovation Lab & Research Platform

## Goal

M19 adds an isolated experimentation layer for evaluating future AI capabilities
without changing production behavior. Experiments are disabled by default,
owned by the current principal, and promoted only through explicit quality and
safety gates.

## Architecture

The research module follows the existing API → service → model pattern:

- `ResearchExperiment` stores a hypothesis, versionable configuration, success
  criteria, and a research-only feature flag.
- `EvaluationDataset` records dataset version, modality, schema, provenance,
  and sensitive-data classification. Dataset contents remain outside Git.
- `ExperimentRun` captures model parameters, quality metrics, latency, and
  safety results.
- `IncubatedFeature` tracks an idea through `idea`, `prototype`, `validated`,
  and `production` stages.

Production modules do not import the research module. Research flags use the
`research.*` namespace and start disabled.

## Evaluation and safety

Run evaluation supports arbitrary numeric quality metrics and explicit success
criteria. Production promotion additionally requires passing:

- truthfulness
- privacy
- bias
- prompt-injection resistance

The benchmark service compares model quality, latency, and safety pass rates.
It is provider-neutral and can evaluate local Ollama models or configured
providers without changing the experiment contract.

## Experimental capability areas

The lab supports experiments for:

- agent workflows and checkpointed orchestration
- multimodal resume and portfolio analysis
- voice interaction foundations
- prompt evaluation
- model evaluation
- research pipelines

These are experiment categories, not production claims. Implementations should
be contributed as isolated adapters and validated against sanitized,
version-controlled dataset manifests.

## Contributor workflow

1. Define a falsifiable hypothesis and measurable success criteria.
2. Create a `research.*` feature flag; leave it disabled by default.
3. Register a sanitized evaluation dataset with provenance.
4. Run a baseline and candidate model with the same dataset and parameters.
5. Record quality, latency, and all required safety checks.
6. Compare results in Model Benchmarks.
7. Incubate the winning feature.
8. Promote only after repeatable validation and code review.

Never commit resumes, portfolio files, audio, images, credentials, or raw
personal evaluation data.

## APIs

- `GET/POST /api/v1/research/experiments`
- `PATCH /api/v1/research/experiments/{id}`
- `POST /api/v1/research/datasets`
- `POST /api/v1/research/experiments/{id}/runs`
- `GET /api/v1/research/benchmarks`
- `POST /api/v1/research/incubator`
- `POST /api/v1/research/incubator/{id}/promote`

## Validation

M19 includes API and service coverage for experiment creation, model
benchmarking, successful gated promotion, and rejection of unsafe or
unevaluated production promotion.
