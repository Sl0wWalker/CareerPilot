# M11 — Beta Launch and User Feedback Platform

## Outcome

CareerPilot now includes an internal beta program with explicit privacy choices,
feedback and bug reporting, satisfaction collection, stable/beta release channels,
feature flags, rollout controls, experiment data foundations, and an owner/admin
product-health view.

## Privacy model

- Analytics and diagnostics are off by default.
- Usage events are rejected unless the authenticated user opts in.
- Diagnostic attachments are discarded unless diagnostic sharing is enabled.
- Usage events use a caller-provided anonymous identifier and never require career
  facts, resumes, application answers, or contact information.
- The implementation is local-first. Feature flags and remote configuration are
  stored locally and exposed through a provider-neutral API that can later be
  backed by a signed remote configuration service.

## Architecture

- `models/beta.py` contains preferences, feedback, survey, analytics, flag, and
  experiment persistence.
- `services/beta.py` owns preference creation, deterministic rollout evaluation,
  and product-health aggregation.
- `api/beta.py` exposes user and role-protected admin APIs.
- `BetaWorkspace.tsx` provides Beta Settings, Feedback Center, Release Channels,
  and an admin product-health dashboard.

Feature rollout uses a stable SHA-256 bucket derived from flag key and anonymous
subject. This makes evaluation deterministic without transmitting identity.

## API summary

- `GET/PATCH /api/v1/beta/settings`
- `POST/GET /api/v1/beta/feedback`
- `POST /api/v1/beta/satisfaction`
- `POST /api/v1/beta/events`
- `GET /api/v1/beta/flags`
- `GET/PATCH /api/v1/beta/admin/feedback`
- `GET /api/v1/beta/admin/health`
- `GET/POST /api/v1/beta/admin/flags`
