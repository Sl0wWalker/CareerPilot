# M9 — Production Readiness, Integrations, and Release Engineering

## Outcome

M9 establishes the production-quality release boundary around the features delivered
in M0–M8. The local-first workflow remains the default; production settings fail
closed when authentication or a strong secret is missing.

## Release foundations

- Versioned `/api/v1` authentication endpoints with PBKDF2 password hashing and
  signed, expiring access tokens.
- Owner/member role foundations and reusable role dependencies.
- Persistent audit events for privileged operations.
- Request IDs, structured request logs, security headers, trusted-host validation,
  CORS configuration, and bounded in-process rate limiting.
- Liveness, readiness, diagnostics, and lightweight process metrics endpoints.
- Replaceable TTL-cache and bounded background-job abstractions for one-node installs.
- SQLite backup API plus guarded PowerShell backup and restore scripts.
- Non-root API container, multi-stage web container, nginx hardening, named data
  volume, health checks, and production Compose profile.
- GitHub Actions for Python lint/tests/migrations, frontend lint/tests/build, and
  pull-request dependency review.

## Configuration profiles

Development defaults keep authentication disabled for the existing single-user local
workflow. Production requires:

```text
CAREERPILOT_ENVIRONMENT=production
CAREERPILOT_AUTH_ENABLED=true
CAREERPILOT_SECRET_KEY=<at least 32 random characters>
```

Never commit the production secret. Staging should use production security settings
with isolated data and origins.

## Operations

Local backup:

```powershell
.\scripts\backup.ps1
```

Restore (the source must be under `data/backups`):

```powershell
.\scripts\restore.ps1 -BackupPath .\data\backups\careerpilot-YYYYMMDD-HHMMSS.db
```

Production container start:

```powershell
$env:CAREERPILOT_SECRET_KEY = '<random value of at least 32 characters>'
docker compose up --build -d
```

The API container applies migrations before serving a new release. For a manual
installation, run:

```text
alembic -c apps/api/alembic.ini upgrade head
```

## Intentional extension points

The local worker and cache interfaces are deliberately small. A multi-node deployment
can replace them with a durable queue and shared cache without changing domain
services. Metrics are dependency-free and expose tracing correlation via request IDs;
OpenTelemetry exporters can be added at the application boundary.

## Release checklist

1. Run backend and frontend tests, linting, type checking, and builds.
2. Apply migrations to a restored copy of production data.
3. Create and verify a backup.
4. Set production secret, allowed origins, and trusted hosts.
5. Build containers and inspect dependency-review results.
6. Verify `/health`, `/ready`, and `/diagnostics`.
7. Perform a supervised application dry run; never automate CAPTCHA bypass.
