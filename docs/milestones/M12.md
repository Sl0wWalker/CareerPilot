# M12 — Cloud Sync, Collaboration & Ecosystem Integrations

## Outcome

M12 adds optional multi-device synchronization and ecosystem integration foundations while
preserving CareerPilot's local-first behavior. Core functionality still requires no cloud account.

## Offline-first synchronization

Clients register a device and exchange immutable changes using cursor-based pull and batched push
APIs. Changes cover profiles, resume metadata, settings, and application history. Each change
contains a base revision, revision, canonical checksum, and payload. Concurrent edits from
different devices create explicit conflicts; CareerPilot never silently overwrites them.

Conflict resolution supports keeping either version or supplying a user-reviewed merge. Device
access can be revoked without deleting local data.

## Connected accounts and integrations

The integration registry describes Gmail, Google Calendar, Google Drive, OneDrive, Dropbox, and
LinkedIn import/export capabilities. Connections are optional and scoped. CareerPilot stores only
a credential reference—not raw OAuth tokens—and returns no credential references through APIs.
Actual provider OAuth exchanges belong in deployment-specific adapters and secret stores.

LinkedIn support is deliberately limited to user-authorized import/export where permitted; M12
does not automate LinkedIn browsing or scraping.

## Collaboration

Workspaces support owners, admins, editors, and viewers. Members receive explicit resource
permissions such as `resume.read` or `application.write`; workspace access does not imply access
to the owner's complete Career Knowledge Base.

## Third-party foundation

Webhook registrations use an allowlisted event vocabulary and reference externally stored
secrets. Future adapters can dispatch signed events through a background worker. The M12 API is
the stable boundary for provider-specific OAuth, file transfer, email import, and calendar export.

## API summary

- `POST/GET/DELETE /api/v1/sync/devices`
- `POST /api/v1/sync/push`
- `GET /api/v1/sync/pull`
- `GET/POST /api/v1/sync/conflicts`
- `GET /api/v1/sync/integrations`
- `POST/GET/DELETE /api/v1/sync/accounts`
- `POST/GET /api/v1/sync/workspaces`
- `POST/GET /api/v1/sync/workspaces/{id}/members`
- `POST/GET /api/v1/sync/webhooks`

## Security and privacy

- No provider tokens are stored in application tables.
- Connected accounts are isolated by authenticated user.
- Sync changes are user-scoped and devices can be revoked.
- Conflicts require deterministic or user-reviewed resolution.
- Collaboration follows least-privilege permissions.
- Cloud features remain optional and local operation is unchanged.
