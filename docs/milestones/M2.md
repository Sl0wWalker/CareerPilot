# M2 — Resume Ingestion and Career Knowledge Pipeline

## Outcome

M2 converts PDF, DOCX, and UTF-8 TXT resumes into reviewable, structured career
facts without an LLM. Imported text and temporary facts remain separate from the
canonical M1 profile until the user approves them.

## Architecture

The API retains the M1 router → service → repository separation. Resume parsing is
an independent pipeline whose components are injected through replaceable classes:

```text
binary file
  → format-specific extractor
  → text cleaner
  → order-independent section detector
  → deterministic entity parser
  → fact validator
  → ParsedFact records
  → user review
  → canonical career profile
```

`ResumeImport` records checksum, parser version, status, source metadata, warnings,
and extracted text. `ParsedFact` records JSON payloads, source references,
confidence, and approval decisions. A SHA-256 uniqueness constraint prevents
duplicate imports.

## Deterministic parsing

The first parser version uses heading aliases, regular expressions, bullet cleanup,
date ranges, and delimiter-based grouping. It recognizes Summary, Experience,
Education, Skills, Projects, Certifications, Awards, Volunteer, and Publications
without assuming a fixed order. Supported canonical facts in this version are
experience, education, skills, projects, certifications, and achievements.

Warnings identify duplicate skills, duplicate companies, malformed entries, and
overlapping employment dates without rejecting otherwise readable resumes.

## Review and approval

The local dashboard provides drag-and-drop upload, progress state, import history,
editable JSON payloads, per-fact accept/reject controls, warnings, and final
approval. Approval writes supported facts to the M1 canonical tables. Rejected
facts remain part of the import audit trail and are never promoted.

## Extension points

- Add an extractor by implementing `BaseExtractor`.
- Replace cleanup, detection, parsing, or validation through pipeline constructor
  injection.
- Add new entity types by extending `EntityParser` and the approval mapper.
- Increment `parser_version` whenever parsing behavior changes materially.
- Add richer deterministic date and contact parsers without changing the API.

## Future AI integration

Future milestones may add an AI parser as an optional pipeline stage after
deterministic extraction. It must emit the same `ExtractedFact` contract, retain
source evidence, and remain behind user review. AI output will never write directly
to canonical career tables.
